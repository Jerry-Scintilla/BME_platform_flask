# 项目营工作区与灰测交付

2026-10-16，前后端交付分支均为 `feature/camp-group-core`。项目营工作区及发布收尾已完成，本地相关检查通过，交付给服务器灰测；本轮不执行服务器部署。工作在独立目录进行，整合既有已提交的积分依赖，未改动积分开发目录。

## 已实现

进入项目营后使用固定头部、工作范围选择器、单条功能侧栏和右侧工作页。负责人和成员的项目合并在一个选择器中显示职责；切换项目保留可用栏目。老师默认进入全营范围，可以查看总体看板、项目只读详情、组会和营期管理功能。双身份账号沿用服务端有效视角切换。

节点与交付采用节点列表及选中详情。材料提交、历史版本、评分与评价仍复用既有业务组件和后端完成计算。草稿只在当前营期工作区会话内按项目、节点隔离保留；切换栏目不会清空，刷新或离开工作区不承诺保留未提交文件。项目成员、成果登记及项目广场发布、组会、独立活动考勤、开启的周考勤均保留入口。

积分和公告明确显示为营期事务，仍使用现有奖励数据与权限；培训营继续使用学习工作台。普通成员的结营项目读取原冻结档案，只提供快照中的节点、成员和成果，不再根据当前有效小组关系重新计算历史进度。

URL保存 `sid/scope/unit/tab/node`。新节点通知使用明确的 `project_node` 来源和节点ID，经只读授权端点解析所属项目。无效项目或节点不会自动显示首个项目的可写提交表单。历史 `camp_project` 通知保留营期级入口，不把混用的旧source_id强行解释成节点。

发布收尾补齐同营期内通知跨项目定位、延迟定位响应取消、老师同页切换节点，以及成员名单变更后的上下文静默刷新。创建模板后交付节点即时更新。人员页显示每个人的项目与职责，直接加人按 member 入营；组队期选人仍由项目负责人操作，开营后的项目人员变更和负责人转交仍由平台管理员处理。培训营继续使用原学员/导生用语和默认行为。

考勤开启时保留个人周累计、负责人项目周表和老师全营考勤；免考勤人员不伪装为零出勤。请假按原营期能力与审批权限执行。结营老师名单来自项目冻结快照，报名审批入口收起，公告只读。

新增只读端点：

- `/camp/projects/<sid>/node-target/<mid>`：验证营期与当前参与／老师授权后返回项目定位。
- `/camp/units/<uid>/members`：仅返回当前项目有效成员的ID、姓名、职责，不返回候选或跨项目志愿。
- 原老师组会接口增加可选 `unit_id`，先验证本营项目，再分页聚合。

## 本地启动

后端 `scripts/preview_project_workspace.py` 仅连接本机MySQL，使用单独的 `bme_workspace_preview_20261016` 数据库、5016端口、独立的本地附件目录和开发账号。它不导入生产app启动器，不启动营期、积分发放、身份巡检或其他定时任务，也不启用外部积分中心。已有演示数据会保留，不自动清库。

从后端工作目录运行：

```sh
/Users/icebear/开发/BME_platform/BME_platform_flask/.venv/bin/python scripts/preview_project_workspace.py
```

脚本优先读取工作目录的`.env`，无该文件时从Git主检出目录读取本机数据库连接配置；明确拒绝非localhost数据库主机。所有新建表和演示账号仅写入上述隔离数据库。

从前端工作目录运行：

```sh
VITE_API_BASE_URL=http://127.0.0.1:5016 pnpm --filter @bme/user run dev:test --port 18096
```

试用入口：`http://127.0.0.1:18096/AMEII/dev/project-workspace`。选择负责人、成员、管理老师或双身份账号后，走正常登录接口进入演示营期；头部“切换试用身份”可返回入口。开发账号密码沿用README约定，入口仅在DEV路由中存在，进入前核对隔离数据库健康标识；不进入生产构建。

演示数据包含进行中、申报期、组队期、开启周考勤和请假的项目营，以及培训营兼容和结营冻结样例。健康端点 `/preview/health` 返回这些营期的ID。可实际提交、评价、组队、加人、请假审批及登记成果，修改仅保存在演示库。前端`.env.development`保持5001，不指向模拟环境或生产。
