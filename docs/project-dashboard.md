# 项目营总体看板

2026-10-14，`feature/camp-group-core`，无数据库迁移。

## 入口与权限

用户端进入自己受委任的项目营，老师工作台默认打开“项目总览”。管理端在营期工作区的“项目营工作区 → 项目总览”查看同一数据。培训营继续使用原老师概览和学习进度。

新增 `project.read_all`，赋予本营活跃的 `CampStaff.owner/teacher`；平台管理员也可查看。项目负责人或普通成员仅凭参与身份不能读取全营看板。权限每次请求复查，解除委任立即阻止看板读取与附件换签，已签发附件地址下载时也复查本营授权。

该权限只开放读取进度、项目名单、最新材料、节点评价与成果，不开放提交、评价、验收、配置、人员调整等写操作。老师需要在对应项目营被委任，不按全局历史角色字符串或其他营的老师身份放行。

## 看板内容

- 全营项目与成员数、节点完成率、逾期项目、待管理员验收材料、待负责人评价成员、核验成果。
- 每行一个项目：负责人、当前成员数、完成情况、当前未完成节点、下一截止、需关注事项、最近更新。
- 按项目实际节点标题生成进度矩阵，同一项目的重复标题独立编号；项目没有某列节点时显示“—”。
- 搜索项目、负责人、成员，筛选逾期、待验收/评价、未配置、负责人缺失、7日内截止、成果待核验、全部完成及项目状态。每页20个项目，顶部统计保持全营口径。
- 点击项目或节点查看只读详情、各成员最新材料及附件、评价（含0分）和成果。附件沿用JWT换短签下载。
- 导出当前筛选的全量名单与节点状态为CSV，包含UTF-8 BOM；防止名称被解释为CSV公式。

## 数据口径

`services/camp_groups/delivery.progress()` 是完成计算唯一来源。多人项目当前有效成员除负责人全部评齐才完成，单人项目最新负责人材料通过管理员验收才完成。人员进出后的状态按读取时当前名单计算，未使用历史 `milestone.status` 代替计算。

完成率 = 完成节点 / 已配置节点，采用节点总量加权。项目无节点时完成率为null、显示“未配置节点”，不当作0%或100%，不计入已完成项目。营期成员数按有效营期成员计一次，项目人数包含负责人，多项目参与者在各项目分别出现。

“待评价”统计已提交有效最新材料而未被评价的成员节点关系；未提交的成员不计待评价。“待验收”沿用现有管理员交付队列。截止日期按亚洲/上海日历判断，截止当天不逾期。暂停/终止项目不产生实时逾期、待验收和待评价提醒，仍展示其已记录进度。

已结营时读取 `CampArchive.snapshot`，不从后续变动的有效名单重新计算；暂停实时待办和逾期提醒。无档案返回409并展示原因，不用实时状态冒充历史事实。旧档案没有项目/节点ID时使用冻结序号定位；新冻结档案额外保存项目ID、节点ID、成员用户ID供稳定识别，不重写存量档案。档案修正依然沿用专用修正记录入口，原始冻结事实不变。

## 接口与查询

- `GET /camp/projects/<sid>/dashboard`：全营摘要、矩阵列和项目行，不含材料正文或评价明细。
- `GET /camp/projects/<sid>/dashboard/<project_key>`：单个项目详情，验证项目属于指定营；结营项目key形如`archive-0`。

列表按营期批量读取有效成员、节点、评价、最新版本和成果。历史提交版本在SQL中排除，没有按节点逐条取数。详情仅读取选中的项目，附件不暴露存储object_key。
