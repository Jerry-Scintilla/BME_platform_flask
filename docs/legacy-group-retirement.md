# 旧小组兼容与退役清单

2026-10-11，第五阶段代码收口。仅盘点仓库源码和执行隔离定向检查；没有连接业务数据库、
读取生产调用日志、迁移数据或关闭仍有消费者的历史入口。社团与工作区不在本清单内。

## 当前权威来源

| 范围 | 读取与写入 | 保留部分 |
| --- | --- | --- |
| 未切换培训营 | `CampMember.team_mentor_id` 读取历史列；原招生窗口/名额/资格校验后由 `recruitment.assign` 更新旧列与配对账本 | 原大一选导生、名片、单一招生归属；不会凭空生成核心组 |
| 已切换培训营 | 招生从 `recruitment_unit_id → TrainingGroupProfile.recruitment_mentor_id` 推导；教学职责来自核心，课程责任来自分配行 | JSON 和 SQL 查询继续支持 `team_mentor_id`，但它是读投影；物理列不再同步写入 |
| 已绑定项目单元 | `UnitMembershipRead` 只读核心成员；组织变更通过 `projects` 应用服务 | 显式旧成员 ID 映射、历史事件及旧成员时间；旧实体 ORM 增改删被拒绝 |
| 未绑定旧项目 | 集中投影读取旧表，修改组织关系须先明确映射 | 历史只读，不以新旧数字 ID 相同作为映射依据 |

`CampMember.legacy_team_mentor_id` 对应原物理列 `team_mentor_id`；这是 ORM 属性调整，不增加
迁移或回填。切换后的无招生绑定、无有效同营绑定均返回空，不回退历史旧值。模型 setter 和
ORM flush 拦截误写；离线迁移与外部直接 SQL 不受 ORM 监听保护，仍须经过维护窗口和核对。
切换后不要用旧数据库物理列直接写业务报表；通过 ORM 兼容属性或显式招生绑定查询。

招生勾选、释放、单人/批量指派、日常改派统一调用写入分流；新营的账本只由培训服务修改。
移除招生导生前仍必须先转交治理负责人；之后释放真实招生绑定和学习职责，课程保留待分配，
不删除学习事实。营期成员退营事件先保存原归属再执行清理。

## 两代旧架构的调用方

离线工具：`.venv/bin/python scripts/inventory_legacy_groups.py`。
本轮静态识别 **56 条相关路由、6 处明确前端调用**；这是直接源码引用清单，不包含动态拼接
URL、仓库外客户端或生产流量。完整输出有路由方法、函数名、源文件及行号，可重复生成。

| 旧架构 / 功能 | 后端入口 | 当前仓库证据 | 处置 |
| --- | --- | --- | --- |
| `GroupModel` 增删与列表 | `/user/group_add`、`/user/group`、`/user/group/list`、`/user/group/delete` | 管理端 `GroupManage.vue` 4 处调用，路由 `/group/manage` 仍注册 | 保留历史请求；不允许承载营期上下文 |
| 旧组进度与排行 | `/learningProgress/group`、`/learningProgress/group_through_courseid` | 管理端 `LearningProgress.vue` 调用旧组列表和进度，共 2 处 | 继续读旧组；不回退或拼接 CampGroup |
| 旧组考勤、请假、通知、任务、作业、奖励 | `user` 的旧组考勤接口、`information` 中旧组相关接口、`medal` 旧组奖励消费者 | 后端仍有 `GroupModel` 读取；当前直接调用扫描未找到对应前端请求 | 保留独立历史语义，生产消费者待核查 |
| `CourseGroup` CRUD、成员与申请 | `/course-groups` 及成员、加入退出、申请审批、进度子路由 | 蓝图仍注册；当前两端源码未发现直接调用 | 未关闭；不推断“没有直接调用”就是生产无人使用 |
| `CourseGroup` 任务与附件 | `/tasks` 及任务、分配、提交附件子路由 | `Task`、`TaskAssignee`、提交及附件表仍注册；当前两端源码未发现直接调用 | 历史任务不迁移、不删除，不作为营期组会任务来源 |

`legacy_boundary` 拦截上述旧组入口明确携带的 `camp_session_id/camp_id/sid/unit_id/camp_group_id`，
返回 409 `LEGACY_GROUP_CONTEXT_UNSUPPORTED`，在旧端点处理前停止；JSON、查询参数与表单均覆盖，
OPTIONS 不受影响。普通旧请求保留原鉴权和语义。营期端点、社团、工作区、普通报错入口不受影响。
这个边界不等于整体退役旧 API；没有营期上下文的旧 `group_id` 始终属于旧命名空间。

## 历史数据盘点准备与退役条件

`scripts/inventory_legacy_groups.py --sql` 只输出数量盘点 SELECT，不执行 SQL、不加载应用配置。
涵盖 `group`、课程组/成员/申请、旧任务/分配/提交/附件，以及按 type 区分的 information。
**本轮未获得数据库存量数字，不能据源码断言这些表为空。**

关闭或删除旧架构前还需：

1. 在确认的目标环境只读采集存量、有效业务范围及附件引用，结合访问日志识别仓库外调用方。
2. 确认管理端两个旧页面及外部消费者退出或另行迁移；明确旧任务/作业/认证如何只读留档。
3. 给出停用入口与实际影响清单，再决定关闭旧创建/修改路由；不靠菜单隐藏宣称退役。
4. 旧营全部切换并完成恢复窗口之后，才评估物理列与旧表删除。本轮没有删列或停用蓝图。

  写入拦截、失败改派保留来源、导生退营、项目范围及旧 API 上下文边界。
- 合并执行本轮和受影响的阶段 2–4 场景共 44 项通过；只做 Python 编译和离线盘点，
