## 备份与结构升级

1. 进入维护窗口，停掉旧 worker、独立调度器及不受营期栅栏控制的写入进程，确认没有旧实例继续处理请求。
2. 记录两仓当前提交与服务配置；保存两个前端静态目录；备份数据库和业务数据目录（含本地附件；对象存储按现有备份策略保留可恢复版本）。核验备份命令成功、文件非空及恢复说明。凭据使用受控配置，不写入命令日志或交接文档。
3. 在独立候选代码目录安装锁定依赖。先确认 Person 层、既有营期及组会结构齐备；不要为了补前置结构盲跑所有历史迁移。
4. 下列脚本无 `--apply` 时只输出离线 DDL。审阅后，在已授权的部署窗口依次执行：

```bash
.venv/bin/python scripts/migrate/migrate_72_group_core.py --apply
.venv/bin/python scripts/migrate/migrate_73_camp_group_binding.py --apply
.venv/bin/python scripts/migrate/migrate_74_training_groups.py --apply
.venv/bin/python scripts/migrate/migrate_75_training_cutover.py --apply
.venv/bin/python scripts/migrate/migrate_76_camp_task_time_precision.py --apply
```

| 迁移 | 作用与核对重点 |
| --- | --- |
| 72 | 五张 CampGroup 核心表；时间列为 DATETIME(6)，已建的早期开发表也会补精度 |
| 73 | 项目营单元 group_id、旧成员映射表及复合外键更新规则；不迁移成员 |
| 74 | 培训组扩展、教学事件、切换标记、学习/考勤资格与课程责任；旧营标记保持关闭 |

- 新培训营只有一套创建流程，自动启用统一组；创建组、双身份视角、课程责任和转交正常。不能审批或认证自己。

- 维护中的营期按约定返回 423，锁等待超时返回 503；解除维护后请求正常。只在独立验收营演练维护操作。

观察日志中的缺表/缺列、403/409 激增、锁超时与提醒异常。存储下载、通知和真实登录链路还需隔离预发布环境集成核查；本机 mock 回归不能代替这些外部服务验收。

## 旧营切换是独立运营动作

本次上线不调用写入型名单工具。需要切换时先单独确定营期、维护窗口、操作人及冲突裁定，再按 [小组服务契约](../group-core.md) 执行 preview → freeze → 重新 preview → map → verify → switch → resume。预览也须使用已经完成结构迁移的数据库，不在缺列旧库上直接跑。

只读预览示例（SID 与新输出路径由操作清单提供）：

```bash
.venv/bin/python scripts/training_group_cutover.py --camp <SID> --action preview --output <新的预览文件路径>
```

成员/课程归属冲突未裁定时不得切换；不直接改 `training_groups_ready`。跨营进度继承尚未启用，默认不自动继承历史课时或评分。社团、工作区不纳入此次抽象。前两代小组接口暂保留，见 [退役清单](../legacy-group-retirement.md)。

## 回退与恢复

- 尚无新组业务写入：停新服务，确认差异仅为本次增量结构后，可恢复原两仓提交与原前端产物；新增结构可保留，不用删表/删列作为快速回退。若需数据库恢复，按已核验的备份恢复流程恢复数据库及匹配的数据目录，再启动对应代码。
- 已有新组、课程转交、认证或映射后的业务写入：保持维护并导出现场，不能直接回旧代码或关闭切换标记。优先修复前进；如必须恢复备份，先评估备份之后新增数据，取得明确授权后按同一时间点恢复代码、数据库、附件/数据目录和前端产物。
- 仅撤销某次旧营映射：使用契约中的 freeze → verify/export → restore → 核对 → resume；出现 `MIGRATION_FORWARD_ONLY` 时停止，不能强制删除新业务。
