# 项目营交付与归档

2026-10-13，修复分支 `feature/camp-group-core`。无需数据库迁移。

## 提交与完成规则

- 多人项目：在职成员提交材料，负责人对除本人外的在职成员逐一评价。所有应评成员评齐即节点完成，0分也是有效评价。成员仅看到本人版本链和评价。
- 单人项目：项目只剩负责人一人在职时，由负责人提交材料，平台管理员验收。最新版通过后节点完成；退回必须写说明，负责人重提新版本。不允许自审。
- 后续成员加入或退出时，读取当前有效名单重新计算完成状态。单人项目变为多人后按多人规则推进，保留原材料和验收历史。
- 模板的 `submit_mode` 列保留以兼容历史数据，已不决定提交主体。用户端申报、模板编辑和管理端平台模板不再提供旧模式选项。
- 管理员的交付队列、营期概览、全局工作台计数及待办列表只统计最新的负责人待审材料，过滤归档营和暂停/终止项目。普通成员材料通过负责人评价推进。

`services/camp_groups/delivery.py` 是完成口径的公共实现。节点接口返回 `completion_mode`（`leader_review` 或 `member_evaluation`）、`node_complete`、派生的 `status`；顶层 `can_submit` 明确当前账号提交资格。写入时同步状态，读取时重新计算，避免成员调整后使用过期状态。

## 附件与通知

单次最多20个附件，合计48MiB，说明最多64KiB。接口限制请求总长49MiB，为生产Nginx现有50MiB限制预留multipart开销；前端提前校验，后端在写存储前校验实际流大小。不修改全站上传限制或服务器配置。

提交串行锁定营期、项目及节点后分配版本，避免重复版本；失败时回滚版本变化并清理本次对象，保留上个版本。业务通知在业务提交前创建，避免依赖审计装饰器顺带提交。单人材料通知有效平台管理员，多人成员材料通知负责人。

管理端和用户端均先携带登录凭证请求附件 `/token`，再打开返回的短签URL。裸下载仍拒绝，短签下载仍重新检查访问权限。

## 结营与只读

项目营状态变更、结营通知、快照和XLab回流在同一事务中提交。任何冻结失败都会回滚结营，不再出现营已关闭而档案缺失。培训营原有学习进度合并路径保持独立。

快照使用与看板相同的完成计算，保存评分、评语、评价人、完成方式和最终材料版本；已完成节点的最终附件标记为资产。存量快照不重写。普通成员读取新快照时只获得本人评价，负责人和管理员可查看本项目全部评价。

归档后普通交付、评价及成果核验/驳回禁止写入。管理员可经专用 `archive/revisions` 接口登记原因和期望版本，保留原始快照。修正使用行锁校验版本。响应中 `archive` 与 `revisions` 是同级字段，前端归档页按此读取；登记修正不受普通业务只读按钮限制。
